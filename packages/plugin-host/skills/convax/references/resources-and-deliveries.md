# Resources and deliveries

## Select and read inputs

Use `convax_graph` to locate the relevant resource nodes and their relationships. File and folder node data contains a path, not its contents. Read needed content with the existing filesystem or document tools, under the Session's current access policy. A folder connection does not change that Session's working directory or writable roots.

A user connection gesture can insert a removable native reference into the selected thread's current draft. The sent message uses the references retained in that draft. Existing graph connections do not silently add their sources on every message, and removing a draft reference does not remove its graph connection. When operating through tools, `edge.add` creates only a relationship; it does not insert a reference into another Chat's draft or send a message.

For an analysis request, read the chosen material, perform the requested work in the current Session, and verify the result. If the user wants a separate conversation to do that work, use the [Chat workflow](chats-and-threads.md); preparing a thread alone does not execute the task.

Window cards retain a selection identity, not screenshot bytes or input authority. Use only an explicitly supplied screenshot or an available authorized capture capability. A graph read cannot establish what a window currently displays. Browser and terminal cards likewise do not make their live content part of the message history.

## Return results to the canvas

When the user needs a file result on the canvas, create and verify the final file, then use the native `present` tool with its existing path. Convax projects the recorded delivery into a file card and a delivery connection from the owning Chat. This also supports delivery recovery after a view closes. A plain response is sufficient when the user only needs an answer.

Do not also add a second file card for the same delivery. A handwritten path in the answer or a manually created `delivery` edge does not substitute for a recorded delivery. `present` is for final files; if the user must review an unfinished file before answering a question, link the current file instead.

For a bound Chat, verify the file's actual contents and the tool's delivery result. Read the graph when the user specifically needs its placement or grouping checked; do not start polling unrelated canvas state. If delivery has not appeared or reports a failure, describe that state accurately rather than claiming a visible card or recreating the work.
