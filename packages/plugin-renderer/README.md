# @deepseek-ai/dsh-convax-plugin-renderer

English | [中文](README.zh.md)

## Summary

Arrange files, folders, application windows, and conversations on multiple saved canvases. Each Chat card creates, forks, and switches DSH threads with their existing conversation flow, composer, and controls. Browser-style tabs keep open canvases and camera positions as window preferences. Closing a tab preserves its canvas, drafts, and running threads; removing a reference preserves its source file. This optional bundle replaces the main workspace while retaining native settings and plugin management.

## Use this package

The bundle's [profile patch](cordis.patch.yml) separately mounts the [canvas Host](../plugin-host/README.md), canvas renderer, [default node Host](../plugin-inernal-nodes-host/README.md), and [default node displays](../plugin-inernal-nodes-renderer/README.md). It requires an existing Web or Desktop profile with native client services enabled. Disabling the canvas renderer restores the native workspace. Disabling only the node displays keeps the canvas, saved nodes and connections as placeholders. Native DSH tasks continue. The default nodes use the same public contribution APIs as third-party nodes.

New conversations initially use PTC mode and workspace-write permissions. Successful choices in the composer persist through the native Settings service and become the defaults for later conversations, including after a reload or restart. Existing conversations retain their own mode and permissions.

For source-checkout Desktop development, run `pnpm --filter @deepseek-ai/dsh-convax-plugin-renderer run desktop:dev`; after building, `pnpm --filter @deepseek-ai/dsh-convax-plugin-renderer run desktop` reuses the artifacts. The scripts load the outer repository `.env` when present, preserving existing environment values, and run DSH's existing Desktop command from `libs/dsh`. The Convax wrapper passes the absolute outer repository `.convax` path as `DSH_HOME` and `.convax/electron-user-data` as `DSH_DESKTOP_USER_DATA_DIR`. Its selected profile keeps the installed plugins. These bootstrap paths come from the launch environment, not project `.env` discovery. Native [Desktop development defaults](../../libs/dsh/apps/desktop/README.md#develop) remain independent.

The upper-right actions, lower-left view controls, and bottom-center creation dock share the same bar styling. All three bars use compact icon buttons; the upper-right bar aligns with the canvas tabs and native window controls. Hovering or focusing an icon reveals its label; the reset-zoom tooltip also shows the current zoom percentage. Top controls prefer tooltips below them; bottom controls and card toolbar actions prefer tooltips above them, flipping vertically before trying a horizontal side when space is limited. Canvas tabs retain their titles. Canvas-owned icons use named imports from [Lucide React](https://lucide.dev/guide/react); embedded native DSH views keep their own icons. Hovering a canvas tab or creation button adds a background without changing its text color.

Canvas surfaces and resource-category colors follow DSH's light, dark, and system appearance. Resource and Chat ports share the same themed fill, surface ring, and size; graph selection and connection previews consume the same semantic accent. Keyboard focus rings retain the theme's pointer-modality suppression and use its semantic accent when no ring override is present. Document previews preserve source content colors.

**All canvases** in the top-right workspace menu opens a searchable manager with separate active and archived lists, node and Chat counts, and a menu for each canvas. **Rename canvas** edits the title in either list without opening the canvas or changing its archive state. Archiving closes its tab without stopping conversations or changing Session archive state; **Undo** restores it to the active list. Unarchiving makes it available to open again. **Duplicate canvas** opens an independent copy with new card and connection identities, the same file paths and positions, and fresh Chat threads without the original conversations or drafts. **Permanently delete…** requires confirmation and clears the canvas and its undo history; original files and Session history remain, and its running conversations are stopped and archived. A failed deletion retains the canvas and offers the saved operation's **Retry** action.

**Activity** in the top bar collects completion and pending-interaction notices across canvases. Its badge counts unread notices; opening the popover keeps them unread. Selecting a notice reopens its canvas, selects and expands the target Chat thread, and reveals it with a brief highlight, preserving zoom when it fits. Only successful navigation marks the notice read. **Mark all as read** clears unread badges without answering pending requests. Read pending notices remain until resolved, and the latest completed notice per Session remains available for the current client lifetime. Removing a Chat clears its activity.

**Automation** in the top bar opens DSH's [task manager](../../libs/dsh/packages/client/ui-schedule/README.md) over the canvas, including tasks from other canvases and Sessions without a Chat card. Selecting a task opens its native rules and saved delivery records; **Linked session** opens its existing canvas, selects the thread and reveals the Chat. An available, unbound Session becomes a Chat in the current canvas with its existing history and task bindings. **New** creates a Chat in the current canvas using its default working directory and prepares an automation request in its native composer for the user to complete and send. A thread with active tasks exposes the native reminder clock beside its tab controls; task details use that thread's existing right-hand tools pane.

The transparent top bar overlays the canvas and contains browser-style canvas tabs, the new-canvas action, Activity, Automation, and the workspace menu. Its empty area moves the Desktop window; tabs and controls retain their own interactions. A 120px window-drag area remains available beside the tabs, or 96px at narrower widths. Extra tabs move into **All canvases**, keeping the active canvas visible. At narrow widths, only the active tab remains and Activity and Automation move into the workspace menu. On macOS Desktop, it shares the native titlebar row through the frame's [integrated titlebar support](../../libs/dsh/packages/client/ui-layout/README.md#window-chrome-seat). Each tab contains its title and close action. Inactive tabs reveal their close action on hover or keyboard focus; devices without hover keep it visible. Drag a tab title horizontally to reorder it. The tab follows the pointer while visible neighbors animate aside. Releasing the tab animates it into its saved position. Release to save the order, or press Escape to cancel. Focus a tab and press Alt+ArrowLeft or Alt+ArrowRight to move it with the keyboard. The order is remembered when the client reopens. Double-click a tab title to rename its canvas. The workspace menu on the right opens **All canvases**, native **Settings**, and **Plugins**. Canvas-specific actions stay in each row of the manager; selecting a saved canvas reopens its tab. **Plugins** opens the existing manager in a right-side drawer over the canvas. Closing the drawer keeps the selected canvas and its camera unchanged. Closing a tab preserves its saved canvas; deleting a canvas removes its saved document. Failed mutations retain visible content and report an error.

The canvas fills the workspace. Its bottom-center controls use icons with hover and keyboard-focus tooltips. The **+** button opens **Add folder** and **Add files**; **Application window** remains available on supported Desktop clients, and the AI conversation icon opens **New chat**. The dock remains centered when the window narrows; the lower-left view controls move above it when needed. Add folder selects a folder through DSH's directory picker and adds a folder reference; Add files accepts multiple files through the system file chooser. Picker additions start in the current canvas viewport, while existing positions and explicit drop coordinates stay unchanged. Expand a file card to preview its content, or select the card and use its toolbar to open a larger preview over the canvas. Connect cards from the right output to the left input. Hover or select a connection to highlight it and reveal a scissors button at its midpoint. Click the scissors or press Delete or Backspace to cut the hovered connection, or the selection when none is hovered. Editing controls retain their own deletion keys. Hovering or selecting a connection, or selecting either connected card, reveals a moving highlight toward its input; reduced-motion preferences disable that animation. Remove a selected card through its toolbar; removing a reference preserves its source file.

Selecting a card shows its toolbar above the card. When a selected card is removed, the remaining cards stay selected; restoring the removed card leaves it unselected. Toolbar icons keep the same screen size while the canvas zooms. File and folder toolbars provide a zoom action, **Show in file manager**, and **Remove reference**; folder toolbars also provide **New chat**. The zoom action opens a larger file preview or fits a folder card into the viewport. **Show in file manager** locates the file or folder in the system file manager. Chat toolbars provide focus and deletion.

Select at least two cards and use **Group selection** in the selection toolbar or context menu, or press Cmd/Ctrl+G. Drag the group title to move its members together; cards inside the frame retain their own editing, dragging and resizing. Double-click the title or choose **Rename group** to edit it. Use **Add to group** or **Remove from group** in a card’s context menu to change membership; dragging across a frame does not change it. **Ungroup** or Cmd/Ctrl+Shift+G preserves the cards and their connections. **Delete group and contents** removes the members and uses the existing confirmation for Chat threads. The frame follows this window’s current card sizes.

Use **Group color** beside the group title or in its context menu to open the same palette: **Default**, **Blue**, **Green**, **Yellow**, **Orange**, **Purple** and **Pink**. Hovering or focusing a swatch previews it only in this window; choosing it applies the color and closes the palette. Escape or an outside click cancels the preview. Multiple selected groups with different colors show **Mixed colors** and receive one color in a single undoable edit. Selecting an unchanged color creates no edit. Narrow or touch clients use a bottom palette with direct tap actions. Saving disables the swatches; a failed save restores the committed colors and reports the error. Card content and connection colors remain unchanged.

On macOS Desktop, **Application window** in the creation dock lists running windows by title with their application icons, falling back to a generic window icon when unavailable; it does not capture thumbnails. Select one exact window to create a read-only mirror card. Its toolbar provides **Choose another window**, **New chat**, focus, and removal; expanding, collapsing, and resizing follow resource cards. The mirror does not forward clicks, keyboard input, or audio. Folding the card or switching canvases releases its view while retaining the capture for unsent references; removing/rebinding the node or unloading the renderer stops it. Copies and client restarts require explicit reselection instead of reconnecting by saved native id or matching title.

A disconnected card offers **Reconnect** and **Choose another window**. Reconnect retries the exact source retained during the current renderer lifetime, preserving the card, edges, and unsent references. Both connection actions are disabled while connecting. A failed attempt retains the actions so you can restore the window, check screen recording permission, and retry. If no source identity remains after a restart or copy, Reconnect opens the window picker for explicit selection; it never substitutes a window with the same title.

Connecting a window to a Chat inserts a removable reference into the captured thread draft. Creating a Chat from the card uses the canvas working directory and connects the window. On sending, retained window references capture fresh images and submit them with the text through native DSH attachments. Removing a reference leaves its edge; saved edges do not restore consumed references. Queued messages keep submission-time images, and history retains them independently of the live window. Capture failure restores the native draft instead of sending stale pixels. Window references do not change Computer Use presets or authorization.

File and folder cards start at 320px wide with one opaque surface and rounded border around their header and content. The header contains the expansion arrow, type icon, and name on the left, with metadata on the right; a divider separates expanded content. Full paths stay hidden. Files and folders added through pickers or drag-and-drop start expanded; existing cards retain their expansion state. Ports stay mounted at the card sides through expansion and collapse. Directory previews start at 240px high and scroll inside the resizable card while its header stays visible. Select a file to preview it. Expanded folder and document previews start at 240px high, audio at 104px, and video at 16:9; saved preview dimensions take precedence. Audio height remains at least 104px, other previews at least 160px, and card width at least 320px. Drag the grip outside the lower-right corner to adjust the card width and preview height, or focus it and use the arrow keys. File, folder, and window cards share the same resize grip, including disconnected mirrors and unavailable-provider placeholders. Collapsed cards resize horizontally without changing their expanded height. Each resource card remembers its expansion, width, and preview height in this window. Preview content scrolls within the card. File previews have an 8px inset inside the card; audio controls provide their own vertical spacing. Images and video preserve their source proportions, and other formats retain their reading layout. [Shared document renderers](../../libs/dsh/packages/client/ui-sidebar-documentpreview/README.md#embedded-previews) display text, code, Markdown, static HTML, images, PDF, and spreadsheets without opening a Session or Sidebar tab. Audio and video previews use native browser playback through versioned HTTP byte ranges. Hover starts a preview and leaving pauses it. Select **Keep playing after the pointer leaves** during hover playback, or **Play** when paused, to keep playing when the pointer leaves, the card collapses, or another canvas opens. **Pause** stops manual playback; background playback exposes a pause control outside the canvas. Removing or replacing the source, unloading the plugin, and closing the client release its player. The larger preview shares the same player and playback position. Click or drag the waveform to seek, or focus it and use the arrow keys, Home, or End. It is the only progress control; while the waveform loads or cannot be decoded, a seek bar occupies the same area. Incremental decoding retains fixed peak bins and bounded sample-copy memory. The volume icon opens its slider on demand. Collapsed audio cards retain play/pause and time in the header, sharing the same player and playback position.

Video metadata shows source dimensions and duration when available. The frame contains the entire video without cropping. Play, seeking, time, volume, and fullscreen share one bottom overlay. The overlay appears when the card is selected or the preview is hovered or contains keyboard focus. Fullscreen, devices without hover, and coarse-pointer devices keep it visible. Paused video offers a central Play button. The volume icon opens a popover with its slider.

Touchpad mode pans the canvas with a two-finger scroll and keeps pinch-to-zoom, while dragging on empty canvas box-selects cards; Mouse mode keeps wheel zoom and drag-to-pan. macOS defaults to Touchpad, while Windows and other platforms default to Mouse. An explicit choice is remembered across canvas tabs and reopening the client.

With keyboard focus on the canvas, press Cmd/Ctrl+A to select all cards, arrow keys to move the selection by five canvas units, and Delete or Backspace to remove it. A hovered or selected connection takes deletion priority. Each movement saves through the Host; a failed save restores the committed position. Escape clears the selection and cancels an active node drag. Cmd/Ctrl+Plus and Minus zoom, and Cmd/Ctrl+0 fits the canvas. Editors, Chat controls, terminals, menus, dialogs, and IME composition retain their native keyboard behavior.

Dragging cards snaps their edges and center lines to other cards and displays alignment guides. A multiple-card selection keeps its relative positions. The snap threshold stays six screen pixels at every zoom. Release the pointer to save the aligned positions together; Escape or window focus loss cancels the drag and clears its guides.

Right-click empty canvas to add a folder, files, or a Chat at that position. Folder creation uses DSH's composed directory picker, including the in-page browser picker and Desktop's native chooser; Chat creation uses the canvas working directory. Right-click a selected card to act on the selection, or an unselected card to act on that card alone; opening the menu keeps the selection unchanged. Empty space inside a multiple-card selection offers the same selection actions. Menus provide focus, removal, select all, and fit actions as appropriate. Editors, Chat content, and terminals retain their native context menus.

The new card and its connection save atomically, using the direction of the original handle. A Chat created from a folder output uses that folder as its project; a file output uses the file's parent directory. Other sources use the canvas working directory. When every thread is archived, the Chat prepares a new thread and composer. Restoring a thread returns its tab to the saved order.

Chat transcript text uses a text cursor and supports native selection and copying; the header retains its drag cursor and moves the card when dragged. The native composer sits below the Chat card without a separate project selector or brand introduction. The Chat card, composer, and embedded tool pane share the 16px radius (`--dsw-radius-lg`). Empty conversations retain a minimum content height. The native tool pane opens to that Chat's right and moves and scales with the same node; each visited thread retains its own editor and tool pages when another thread is selected. The tool pane preserves the Chat's height when opened and scrolls overflowing content within itself. Collapsing the Chat preserves drafts and running work. The native Conversation retains model, permission, tool, and approval interactions.

Drag the grip outside the Chat card's lower-right corner to adjust its width and transcript height. The composer follows its width and grows with its content. Loading and failed Chat views remain resizable; collapsed Chats resize horizontally and retain their transcript height. Attached tools match the Chat header and transcript height, excluding the composer; drag their right edge to adjust their width. Resize grips sit close to the card edge without button backgrounds. ### Application notices

When the [Host notice source](../plugin-host/README.md#client-notices) is configured, feature and update announcements can open a global modal. Maintenance uses the shared Toast/Message surface; generic guidance also supports a banner. Ordinary notices wait while the window is inactive, an input or drag is active, a task is running, or another modal owns interaction.

Closing an ordinary notice uses its configured snooze action when present, otherwise records dismissal. Mandatory update notices have no close button and ignore Escape and mask dismissal. Their update action opens the native updater without automatically downloading or installing a release.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

The renderer contributes to the shell's single `shell.workspace` Slot. Components receive derived Slot props, declared viewing-store actions, and narrow injected callbacks. Generated Remote methods carry revisioned commands to the Host; Client resource providers own live workspace snapshots and file reads. React Flow controls graph gestures without owning durable canvas records. The canvas-owned grouping controller submits Host commands; group frames are derived from current measured card bounds and are not persisted. Node measurements stay in temporary renderer state. Controlled-node updates retain them to keep mounted editors visible during selection and prop updates.

Workspace controls derive busy and history indicators from one active-operation kind; a synchronous submission guard prevents overlapping mutations. Paste and duplicate share the same post-commit sequence: restore card preferences, select the copies, then reveal them with their measured dimensions.

Notifications mount independently in `shell.overlay`, so switching canvases does not unload them. A React-independent window runtime reads browser interaction and task state, requests a Host presentation lease, and passes data and callbacks to the view. Actual visible mounting reports exposure; fetching or queueing a notice does not. Disposal removes activity listeners, drains operations and releases the window's lease.

Desktop drops use a Convax-owned adapter for the existing preload file-path capability. The adapter preserves original File identity and leaves bytes untouched; the Host filesystem authorizes and classifies the resolved path before a reference node is saved. Served Web documents have no native path capability.

The window mirror owner serializes Desktop source preparation and `getDisplayMedia`, retaining streams by node and binding identity. Views attach only to that occurrence, so copied nodes cannot borrow a capture. Native source ids and leases remain runtime-owned. Typed input-trigger preparation resolves the captured reference into submit-owned text and PNG images without changing draft attachment ids. Focus/visibility return and pointer entry revalidate displayed sources; capture independently validates before and after accepting pixels. Disposal stops tracks before draining frame consumers, then releases native leases.

DOM order places the titlebar after the canvas body so clipped `no-drag` regions cannot override window dragging; flex order and `reading-flow: flex-visual` keep the titlebar first visually and during keyboard navigation.

The [viewing store](src/client/store.ts) owns tab order, closed-tab history, input-mode preferences, one camera position per canvas, and per-node resource expansion, width, and preview height. Optional `resourceViews` entries and dimensions keep older window preferences valid and are pruned when workspace reconciliation supplies the remaining node identities. The Host owns canvas documents and their atomic revisions. Plugin disposal removes the Remote contribution, resource providers, active watch streams, and workspace entry.

Chat content uses the public `conversation.header.content` and `conversation.content` Factories under an explicit retained Session provider. The `convax.chat.content` Factory receives Chat metadata, the canvas revision, and node-local focus and removal actions; injected thread actions perform creation and forking. A thread resource owns its visible reference; DSH's Conversation draft owner independently retains unsent text, attachment objects, and unacknowledged sends across view closures. Thread order, selection, and unresolved creation requests use separate window preferences; archived thread identities retain their saved positions. The Host owns unique Session bindings and durable creation receipts, so a retry uses the actual Session already created.

The public `convax.graph` Factory and Chat content share one Chat preference Store. The graph reads only card sizes, collapse state, and tool-panel widths for copying; new cards receive these presentation preferences through declared Store actions. Thread selection, Session bindings, drafts, and open tool pages are not copied.

Client node plugins inject `convaxRenderer` and call `registerNodeRenderer(typeId, { dataVersion, component })`. The returned disposer and the contributing Cordis effect own registration; duplicate active identities are rejected. Built-in references and Chats use this same interface. Components receive framework-derived node props, named ports, revision-bound command callbacks, and Factory rendering. A plugin can supply its own Factory for additional state, localization, and child Slots. `NodePorts` renders declared ports and retained connection endpoints.

Business renderers receive a node only when its Host definition exists, its payload version matches, and the Host reports no migration or compatibility issue. The Client display must also support the exact data version. Missing displays, unavailable providers, and incompatible payloads have distinct localized placeholders; placeholder handles preserve existing edges and refuse new connections.

<a id="model-experience"></a>
## Model Experience

Indirectly, through native DSH Conversation submissions whose retained window references add immutable PNG images with source names, capture times, and dimensions.

#### KV Cache effect

Window screenshots and their metadata increase user-input size without changing the model prefix. Queued delivery and retries retain the same admitted images.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- Audio and video codec support follows the browser and operating system; unsupported formats use system opening. File moves and renames do not rewrite saved references. One Session has one editable composer per Client; distinct threads provide independent editors. Browser-owned draft attachment objects survive view closures while DSH's client remains loaded, but they are not persisted across a page reload or application exit.
- Groups support one level. Nested groups, group folding, automatic membership changes on drag, and resizing a group with its contents are not available.
- Guide bubbles and an announcement history entry are not provided. Notification UI does not enforce service policy or configure a Convax native update feed; the existing Desktop update flow remains its own owner. Cloud delivery and read-state limits belong to the [Host notice source](../plugin-host/README.md#known-limitations-and-deferred-work).
- Window mirroring requires macOS Desktop screen-capture permission and an image-input model for Chat screenshots. Direct mirror operation remains deferred. Minimized/closed windows can leave Chromium tracks marked live; native validation rejects their screenshots and disconnects detected stale sources. Focus, visibility, pointer entry, and submission are detection points, not a continuous window-change subscription. Ordinary browsers cannot silently capture a Desktop Host's window.
