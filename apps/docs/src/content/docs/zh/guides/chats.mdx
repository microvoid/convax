Chat 卡片把多个 DSH 对话 thread 组织在一起。它复用原生对话流和输入框，包括模型选择、权限控制、工具和审批交互。一个 Session 在同一 Client 中只支持一个可编辑输入框；需要独立编辑器时，应使用不同的 thread。

## 选择工作目录

底部创建栏的**新建聊天**使用当前画布的工作目录。文件夹卡片上的**新建聊天**改用该文件夹，并将它连到新 Chat。已有 Chat 保留各自的项目目录。

每张画布默认在 `~/Documents/convax` 下准备稳定目录，重命名画布不会移动它。之后连接文件或文件夹只会添加引用，不会改变 Chat 的工作目录，也不会扩展可写根目录。

## 让 thread 保持独立

在 Chat 顶栏创建、切换 thread，或为对话创建分叉。每个 thread 拥有自己的历史和草稿。切换时，已访问的 thread 保留其编辑器和工具；原生工具面板在所属 Chat 的右侧打开。

输入框底栏的模式选择复用已安装的 DSH 智能体预设。空 thread 可以切换模式；已开始的 thread 保留原模式，要使用不同预设时，可在同一 Chat 中创建新 thread。新任务的默认模式由设置管理。

归档 thread 会隐藏标签，保留其绑定和图中的连线；恢复后标签会回来。全部 thread 都已归档时，Chat 会准备一个新 thread 和输入框。

## 决定消息引用

将资源的输出连接到 Chat 的输入。连线手势会给连线开始时选中的 thread 添加一个可删除引用。发送前，先检查输入文字上方的引用区域。

- 删除引用不会删除连线。
- 发送以当前草稿保留的引用为准。
- 发送成功后，已提交的引用随草稿一起消费。
- 已有连线不会重新补入被消费或删除的引用，刷新后也不会。

浏览器持有的附件对象不会跨页面刷新或应用退出持久化；未发送的附件可能需要重新添加。智能体创建图连线也不会自动插入引用或发送提示。

折叠 Chat 会保留草稿和正在运行的工作；删除前需要确认，之后才停止并归档其 thread。截图引用的行为见[窗口镜像](/zh/guides/windows/)。
