# Convax 国际化

[English](i18n.md) | [中文](i18n.zh.md)

## 概述

Convax 使用 DSH 已有 locale 服务处理语言选择、持久化、字典查找和界面即时更新。Convax 负责自己的 UI 字典、包元数据及检查，第三方插件负责各自命名空间。DSH 运行时保持原样。

## 共享语言偏好

DSH 的语言设置提供 `en`、`zh`、`ja`、`es`、`fr`、`de`、`ru` 和 `pt`，语言包插件还能注册其他语言。显式偏好优先于临时使用的浏览器或 Desktop 系统语言。DSH 通过已有 settings 服务持久化 `locale.preference`。Convax 启动器将 `.convax` 设为应用目录时，这一偏好自然属于该目录，Convax 不另存语言设置。

locale 运行时先在请求的命名空间内沿当前语言回退链查找，再查询 `common`，最后返回键本身。语言回退链最终到达英文。翻译缺失必须由检查发现，不能将英文回退当作已支持所选语言。参见 [DSH locale 参考](../libs/dsh/packages/client/locale/README.zh.md)。

<a id="resources"></a>
## 资源归属

运行时命名空间为 `convax`。[`src/client/locales/en.ts`](../packages/plugin-renderer/src/client/locales/en.ts) 定义键类型，其他语言提供完整字典并保留相同插值参数。[`locales.ts`](../packages/plugin-renderer/src/client/locales.ts) 导出 `dictionaries`、`SUPPORTED_LOCALES` 和 `ConvaxLocale`。renderer 通过 effect 所有的 `ctx.locale.register` 注册这些字典。

包内 `locale/<language>.json` 保存 Plugin Manager 使用的 `meta.title` 与 `meta.description`。它们是包元数据，不再复制 UI 字典。DSH 通过 `ctx.locale.resolveText` 解析这些元数据，不会将任意 JSON 字段自动注册成运行时命名空间。

第三方功能使用带提供方名称的命名空间，例如 `example.counter`。在 `LocaleNamespaceMap` 声明键，通过 `ctx.effect(() => ctx.locale.register(namespace, dictionaries))` 注册字典，并保留 `{name}` 等具名占位符。贡献者不向 Convax 中央字典添加自己的键。

<a id="plugins"></a>
## 插件渲染

Slot 与 Factory 声明携带 `locale` 命名空间。注入的 `t` 随 locale revision 更新，使已挂载和使用 memo 的界面获得新文案。`ctx.locale.bind(namespace)` 返回稳定函数，每次调用时读取当前语言；应在渲染时调用，而非注册时保存翻译结果。Slot／Factory 之外的组件需要订阅 `ctx.locale.getSnapshot` 与 `ctx.locale.subscribe`，再派生展示文本。

节点 renderer 接收 Convax 的翻译席位，用于通用卡片行为。业务内容需要自己的翻译席位、store 或子 slot 时，通过声明自身 locale 的 Factory 包装。小型组件也可以像随附示例一样，在节点渲染回调中调用已绑定的命名空间函数：

```js
const t = ctx.locale.bind('example.counter')
ctx.inject(['convaxRenderer'], (scope) => {
  scope.convaxRenderer.registerNodeRenderer('example.counter', {
    dataVersion: 1,
    component: props => h(Counter, { ...props, title: t('title') }),
  })
})
```

此片段假设插件已注册字典并提供 `h` 与 `Counter`。完整可运行实现见[计数器示例](../packages/plugin-renderer/examples/counter/client.js)和 [canvas-note 模板](../packages/plugin-host/templates/canvas-note/client.js)。两者保留各自命名空间，并在渲染时翻译标签。

公开的第三方工具栏动作 API 尚未实现。设计中必须携带插件 locale 命名空间与 `labelKey`，由 renderer 使用当前翻译席位解析标签、tooltip 和执行反馈。未来注册不能在插件激活时将 `label: t("action")` 固定成字符串。这是 API 设计要求，不是当前可用的注册方法。

## 错误与持久标题

Host 诊断保留供调试，面向用户的说明在 Client 本地化。命令失败保留 `conflict`、`not-found`、`invalid-command` 等稳定 `code`；节点问题使用稳定的 `kind`，Chat 问题使用 `issueCode`（`thread-create`、`deletion`、`delivery` 或 `chat-unavailable`）。原始 `message` 与 `issue` 文本放在可展开的技术详情中。Client 不能通过匹配英文文本推断错误类别。

画布可通过 `titleFormat` 保留系统命名规则：`default` 显示本地化未命名标题，`literal` 保留其 `value`，`copy` 递归显示 `source` 并应用当前语言的副本名称模板。已有 `title` 保留为字面回退值。显式重命名移除命名规则。Chat 节点的 `data.defaultTitle: true` 表示显示当前语言的未命名聊天标签，不把保存的回退标题当作用户文本。

旧记录缺少这些标记时保持字面文本，包括恰好等于某种语言默认名称的标题。迁移不根据标题字符串猜测归属。切换语言不重写用户标题、文件路径、笔记正文或 Session 消息。schema 升级与恢复副本由 Convax 负责。

<a id="verification"></a>
## 格式与验证

面向用户的日期和数字通过 `Intl.DateTimeFormat` 与 `Intl.NumberFormat` 显式使用当前 DSH locale。媒体时间码和协议值等明确的机器格式保留规定表示。用户已在 DSH 选择语言后，不再由浏览器另一个默认语言决定格式。

在外层 Convax 仓库运行以下检查：

```sh
pnpm run check:i18n
pnpm run test:i18n:e2e
```

静态检查覆盖 Convax 自有字典、包元数据、示例和模板，检查语言或键缺失、插值参数变化、不可见字符及嵌入的 UI 文案。浏览器 E2E 使用正式 Web 组合与真实语言设置，验证已挂载卡片、偏好持久化和用户内容保留。每一步实现后运行对应 E2E，使用已有产物的浏览器检查要求产物保持最新。这条语言切换路径不需要 API key。
