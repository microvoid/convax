# Agent Note: Convax 可交互窗口镜像节点

Status: proposed

[English](2026-11-02-convax-window-mirror.md) | 中文

## 问题

用户需要把应用窗口放到画布上，通过镜像操作原窗口，并连到能够看到窗口当前内容的 Chat。已保存连线不能变成持续的模型输入，也不能覆盖输入框对 reference 的所有权。

本提案扩展[画布方案](2026-10-28-convax-canvas.zh.md)与[插件开发方案](../architecture/2026-10-30-convax-plugin-development.zh.md)。它保留 [Computer Use 提供方](../../implemented/architecture/2026-09-12-computer-use-provider-registration.zh.md)、[应用授权](../../implemented/architecture/2026-09-26-cua-application-consent.zh.md)和[共享原生 helper](../../implemented/architecture/2026-10-09-cua-shared-native-helper.zh.md)的决策，不取代其中任何一项。直接操作仍处于提案阶段；下文记录只读实现与原生验证。

## 提案

### 已确认行为

| 主题 | 已达成一致的行为 |
|---|---|
| 绑定 | 每个节点绑定用户明确选中的具体应用窗口，不跟随应用当前活跃窗口。 |
| 操作 | 点击、拖动、滚动及输入控制原窗口仍是最终目标，但推迟到用户验收只读镜像、Chat 接入、恢复及 Computer Use 验证之后。 |
| Chat 输入 | 提交消息时，为当前草稿保留的每个窗口 reference 采集最新截图。模型收到固定图片，不接收实时预览流。 |

其余细节是交付这些要求的默认方案。本轮交付停在只读镜像、发送时截图及 Computer Use 有效性验证；之后由用户实测，再讨论和实现镜像内直接操作。当前阶段镜像预览不转发指针或键盘输入。

### 创建与卡片交互

通过现有 Host 与 renderer 节点注册机制注册 `convax.window`。在现有资源操作旁增加“应用窗口”次级创建入口。选择器先通过名称及图标列出运行中的应用和各个窗口；仅为已授权应用采集预览，其余在选中并完成现有授权流程后生成。打开选择器不能提前截取所有未授权应用。添加节点不启动应用，也不隐式选择其当前活跃窗口。

卡片与资源卡片对齐：紧凑标题栏包含展开折叠、应用图标、窗口标题、端口及菜单；下方可展开内容区承载实时镜像。选中卡片的操作提供适配、重新绑定、新建 Chat 和移除。移除节点保留源窗口。沿用外部尺寸手柄及现有 hover、渐隐行为。

```text
                 [Fit] [Rebind] [New Chat] [Remove]
  o  [v] [App icon] Window title              [...]  o
     +---------------------------------------------+
     |                                             |
     |             Interactive mirror              |
     |                                             |
     +---------------------------------------------+
                                [Operating / Exit]
```

拖动标题栏移动节点；操作画面控制源窗口。首次点击画面进入操作，并将该次点击只转发一次。画面手势和滚动不能触发画布平移、节点拖动或创建连线。标题栏控件、端口和外部尺寸手柄仍由画布处理。点击外部或使用明确的“退出操作”控件释放路由；不能无条件占用原应用的 Escape 键。

展示明确的键盘焦点。投递按键前确认选定源窗口获得焦点，仅应用获得焦点不足以保证目标正确。支持文字选择、快捷键、剪贴板及 macOS 系统拼音组合输入，包括首字。验证原生或本地 composition 桥接，不将 composing `keydown` 当作文本逐键转发。失焦、锁屏、重新绑定、断连或视图移除时取消路由，并尽可能释放按住的按钮和按键。投递结果未知的输入绝不重放。

坐标映射处理画布平移缩放、卡片调节尺寸、等比显示留白、源窗口尺寸变化、Retina 缩放与多显示器。忽略留白点击，窗口代次或几何变化时拒绝失效操作。同一时刻仅一个镜像拥有活跃的人工键盘路由；其他镜像仍可观看，不引入节点或 Chat 数量配额。人工或 agent 操作造成的原生焦点变化，不能把操作转给另一窗口。

### 连线与 reference 所有权

连接到已有 Chat 时，在其选定 thread 的草稿插入类型化窗口 reference。从窗口新建 Chat 时，创建连线并向第一个 thread 插入 reference。窗口不提供文件系统项目路径：新建 Chat 使用画布保留的默认目录，已有 Chat 保留原项目。

chip 标识应用和窗口，并提示发送时采集新图。它保存源绑定，不保存连线时的截图。删除 chip 保留连线；断开连线不改写保留的草稿 reference。移除或重新绑定源节点后，之前的 reference 不可用，直到用户明确删除或替换。重新绑定不能悄悄替换已有 reference 的目标。

只有提交草稿保留的 reference 决定截图。已保存连线、重开画布、切换 thread 或选中节点不插入 reference。成功沿用原生草稿消费行为；连线不回填已消费的 reference。多个 Chat 可独立引用一个窗口，一个 Chat 也可引用多个窗口。连线或操作窗口都不会自动发送消息。

### 发送时准备

1. 通过原生发送生命周期冻结 thread、草稿、reference 顺序及绑定代次。将截图准备展示为该次提交的一部分，防止重复提交。
2. 提交开始后，校验确切原生租约，并通过 `ImageCapture.grabFrame()` 从 renderer 拥有的窗口流采集新帧。接纳前再次校验，不复用较早的预览图片。多张截图各自保留时间戳，不承诺属于同一桌面瞬间。
3. 创建不可变图片附件。通过现有可序列化消息及附件字段，关联各图片的源应用及窗口、截图时间和尺寸。图片字节存入 DSH 附件存储，不写入画布数据库。
4. 接纳前重新校验绑定代次及取消状态，再通过 DSH 现有 prompt 与附件路径一并接纳文本和全部图片。导航变化也保持提交时捕获的目标 thread。排队消息在入队等待前截图；队列投递、提供方重试及历史重放复用同一组图片，不重新采集。
5. 接纳前任一采集或准备失败，不发送部分消息，保留草稿，在原位置指出失败 reference，并释放未接纳资源。接纳失败沿用原生恢复；结果未知时对账，不自动重发。用户明确发起新提交时采集新图。

窗口关闭、最小化、锁定、不可访问或不受支持时，不能悄悄提供旧像素。只有 provider 验证图片来自确切窗口的当前状态，采集才算成功；否则恢复或重新绑定、重试，或删除该 reference 后发送其余草稿。模型不支持图片时，在消费草稿前报告失败。之后删除节点，仍保留已接纳图片历史，且重放不依赖实时窗口。

### 现有能力与所需扩展

[节点注册表](../../../../packages/convax/plugin-host/src/registry.ts)和 [renderer 注册表](../../../../packages/convax/plugin-renderer/src/client/node-renderers.tsx)提供节点贡献。当前[资源准备](../../../../packages/convax/plugin-host/src/index.ts)校验文件或文件夹路径，[草稿插入](../../../../packages/convax/plugin-renderer/src/client/draft-references.ts)创建原生文件 reference。实时窗口绑定需要明确的 reference 协议。

[原生 CUA 代码](../../../../packages/experimental/cua-macos/native/Sources/CuaNative/)实现逐窗单次截图和局部指针操作，没有连续镜像。键盘操作跟随应用焦点；hover 可能要求原窗口置前。[Computer Use 注册表](../../../../packages/computer-use/computer-use/src/index.ts)仅注册 provider 身份，没有公开截图或输入分发接口。不能虚构 `ctx.computerUse.capture`、使用私有 Agent 闭包，也不能为人工路由伪造 Agent。

[输入框](../../../../packages/client/ui-conversation/src/client/input/facade.ts)为一次提交捕获附件 id，而 [reference 序列化](../../../../packages/client/ui-conversation/src/client/input/prompt.ts)返回文本。若序列化器修改草稿追加图片，该图片不会进入已捕获列表。建议增加类型化异步准备贡献，在现有 sink 接纳提交前，将捕获的 reference 解析成文本及图片输入。明确顺序、取消、临时资源所有权、失败恢复、排队行为和命令附件支持。没有匹配贡献时保留现有 reference 行为，不包装发送按钮，也不创建第二套输入框。

### 运行时与持久化所有权

共享 `dsh-util-desktop-capture` 库定义类型化协议。Desktop 主进程提供精确窗口枚举与一次性采集租约；Convax renderer 消费该桥，拥有只读 MediaStream 并准备发送时图片。DSH Host 持久化图记录，接纳普通图片附件。effect 释放时停止轨道、排空待完成帧工作，再释放原生租约。直接输入路由继续推迟。

评估复用共享原生 helper，避免竞争的采集 helper 或第二个 Computer Use provider。缺少的共享原生或输入框 API 需要基于实际消费方形成范围独立、可测试的扩展。保持 Computer Use 的 `agentPreset: 'ptc'` 默认值及授权规则。人工镜像不切换 Chat preset；截图 reference 不授予 agent 控制工具。人工路由与 agent 工具保留独立入口，并沿用现有操作系统权限要求。

预览帧属于临时数据，不进入画布存储或 Session 事件。运行时选择跨卡片折叠和画布导航保留轨道，使草稿能采集图片，而不暗中通过原生窗口 id 重新取得源。移除或重新绑定节点、卸载 renderer 时停止轨道并释放租约。只读视图独立释放自己的 video 元素。原生采集使用平台帧率，不另建截图轮询循环。

通过 Convax 持久化节点身份及版本、应用身份、展示名称、选择线索、几何与折叠状态。OS 句柄、进程实例 id、流、画面缓冲、焦点及待完成截图属于运行时。裸窗口 id 和 PID 可能复用；相同 id 或标题不能授权自动绑定其他窗口。重启后先展示等待重连，除非 provider 确认是同一个具体窗口；否则需要明确重新选择。

关闭窗口或退出应用保留断连节点及连线。切换源应用当前活跃窗口，不改变目标。复制节点或画布保留展示及选择线索，重新获取句柄，不转移活跃输入路由；现有 Chat 独立复制语义保持不变。遵循节点 payload 迁移规则；改动耐久草稿或附件字段前，对实际已声明持久化类型变化补充确认记录。

先在当前 macOS Desktop 验证原生行为。其他平台及浏览器客户端需要已验证的采集、传输和输入能力，否则保留不可用占位。浏览器不能悄悄用自己的屏幕选择器替代 Desktop Host 上的窗口。权限拒绝或撤销沿用现有引导和卡片内可恢复状态。遮挡窗口的镜像是验证目标；最小化、隐藏和跨 Space 行为需要分别提供原生证据。停滞预览必须标明状态及时间，不能满足最新截图要求。

### 落地顺序

1. 只读镜像可行性：验证指定原生窗口持续更新、遮挡时不换源，以及最小化或关闭时的明确状态。确认资源正确释放后再接 Chat，不实现输入转发。
2. 完整链路：接入节点注册、选择器、只读实时卡片、Chat 创建及连线、类型化 reference，以及经原生输入框和附件流程完成的发送时准备。验证真实窗口到 Chat 的闭环。
3. 恢复：覆盖多窗口及多 Chat、排队、失败、权限、窗口替换或重连、复制及重启、导航和插件释放。为实际交付的实现更新所属包及子系统文档、持久化确认记录。
4. Computer Use 验证：镜像采集运行期间，对镜像目标使用已有工具路径，验证新鲜截图、一次无害操作及可见结果。保持 preset 默认值及授权不变，实际证明共存，不从分别测试成功推导。
5. 用户验收：保留已运行功能供用户实测，并在这里停止。用户验收通过后，再讨论上文描述的直接操作、焦点、坐标、剪贴板和输入法要求。

## 考虑过的替代方案

**跟随应用激活。** 已确认的目标是具体窗口；跟随激活可能在用户切换窗口时发送另一份文档。

**只读截图卡片。** 它省去焦点及输入复杂度，但缺少已确认的直接操作能力。

**连线时图片或缓存预览。** 它可能早于消息；提交拥有的截图为每条接纳消息提供不可变、来源明确的图片。

**持续向模型传输。** 预览与模型输入的生命周期独立。发送时图片保留消息历史，不会因为观看窗口而持续发起模型请求。

**连线驱动永久输入。** 它与草稿所有权冲突，会恢复用户删除或已消费的 reference。以提交草稿为准。

## 验收标准

- 同一应用的两个窗口保持可区分；源选择、焦点变化及复用的原生 id 不会导致输入或截图错投。
- 真实点击、拖动、滚动、文字选择、快捷键、剪贴板及 macOS 系统拼音可通过镜像使用，覆盖缩放、调节尺寸、显示缩放及多显示器。焦点转换时画布保持可用。
- 镜像输入不能平移或拖动画布，也不能向另一个 Chat 输入。外部控件正常工作，退出、断连或释放后松开按住的输入。
- 连线只向选定 thread 插入可删除 reference。删除它保留连线；不含它的发送不采集窗口截图。
- 连线后、发送前修改窗口，提交图片随之变化。提交后变化不影响队列输入、重试或重放。多个源保留附件顺序及来源关联。
- 采集、图片支持或接纳失败时保留草稿并指出来源；不把旧图或部分接纳的替代结果呈现为成功。接纳结果未知时对账，不重复提交 prompt。
- 窗口替换或关闭、锁屏、最小化或遮挡、权限、重启、复制及 provider/renderer 释放均保留图数据，并拒绝不安全采集或输入。
- 各阶段具备聚焦测试和浏览器 E2E；原生 Desktop E2E 验证真实像素、输入及输入法，不把模拟浏览器视频当作平台证据。无 key 录制 Session 用例检查不可变图片历史。真实模型测试使用根 `.env` 的 API key 约定，不记录凭据。

## 风险

控制确切原生窗口且保留可用画布是主要可行性风险。截图成功不能证明键盘焦点、hover 或输入法正确。若平台要求置前原应用，先验证并记录实际 UX，再判断是否等同于内嵌操作。

连续采集增加延迟及资源消耗，且需要与共享 helper 的串行执行及采集失败恢复共存。浏览器测试与录制 Session 重放不能证明原生权限、源当前像素、遮挡行为或输入目标；这些需要发布前的原生证据。
