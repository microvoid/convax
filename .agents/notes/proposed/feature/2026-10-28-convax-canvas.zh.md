# Agent Note: Convax 画布产品与架构提案

Status: proposed

[English](2026-10-28-convax-canvas.md) | 中文

## 问题

Convax 需要以画布作为 Desktop 的主界面，让用户跨多个画布组织文件、文件夹和对话。DSH 已经拥有对话执行、历史、输入和工具交互能力。设计需要在保留这些能力的同时，让画布拥有独立的数据和生命周期。

[插件开发方案](../architecture/2026-10-30-convax-plugin-development.zh.md)进一步说明贡献方式、双宿主适配和 AI 编写决策。Convax 通过普通 DSH 插件注册提供自有[开发 skill](../../../../packages/convax/plugin-host/skills/convax-plugin-development/SKILL.md)和 [canvas-note 模板](../../../../packages/convax/plugin-host/templates/canvas-note/)。

[窗口镜像方案](2026-11-02-convax-window-mirror.zh.md)增加绑定具体窗口、可直接操作的应用窗口，以及发送时截图 reference。

## 提案

以下产品行为已经确定。DSH 现有公开扩展点能够满足需求时，保持 DSH 不变；仅有 Convax 专用需求不足以新增 DSH 运行时 API。Convax 拥有图事务、schema 升级、thread 操作恢复和删除协调。经复现确认的 DSH 缺陷单独修复，并提供对应测试。

### 已确定的产品行为

| 领域 | 行为 |
|---|---|
| 主界面 | Desktop 的主要工作界面是画布，通过浏览器式 Tab 切换多个画布。 |
| 画布归属 | 画布属于应用。一张画布可包含不同项目的文件和文件夹；添加项目就是添加文件夹或文件节点。 |
| 画布存储 | Convax 将画布作为应用管理的数据，自动保存到应用数据位置。用户通过画布列表和 Tab 打开，无需为每张画布选择保存路径。默认介质为独立的 Convax SQLite 数据库。 |
| 存储事务 | Convax Host 自己拥有 SQLite 事务、修订校验和 schema 迁移。Session 消息保留 DSH 原有存储；单一 Convax thread 操作账本在部分成功后协调图与 Session 操作。节点插件使用 Convax API。 |
| 文件和文件夹节点 | 节点引用本地原文件、原文件夹。首版支持目录浏览、将子项拖入画布和文件预览；编辑交给 agent（智能体）或外部应用。移除节点保留原文件。 |
| Chat 节点 | Chat 是画布节点，内部包含多个 thread。每个 thread 对应一个 DSH Session，用户在 Chat 卡片内创建和切换 thread。 |
| Session 绑定 | 一个 Chat 可以拥有多个 DSH Session，但每个 Session 在 Convax 内只绑定一个 Chat。在 DSH 原生界面查看同一 Session 不产生新绑定。在另一个 Chat 延续相同历史时，通过 fork 创建具有新身份的 Session，保持输入选择和删除归档处理明确。 |
| 对话复用 | Chat 嵌入 DSH 现有的对话流、输入框及其已有交互。Convax 不建立第二套对话实现。 |
| 节点扩展 | 其他 DSH 插件可以注册画布节点类型。文件、文件夹、Chat 也使用同一套注册机制。DSH 拥有插件安装、启停和依赖管理；Convax 定义节点类型、数据 schema、连线端口和渲染入口；各节点插件拥有自己的业务数据和行为。 |
| 节点插件不可用 | 停用或卸载节点插件时，保留其节点的完整数据、位置尺寸和连线，显示可移动、可删除的插件不可用占位卡片。该节点的新业务操作不可用，其他节点仍可使用。重新启用或安装兼容实现后恢复原节点。 |
| 节点数据升级 | 节点数据版本独立于插件发布版本。插件提供版本化迁移函数，Convax 自动执行适用迁移并校验，提交前保留可恢复副本。成功后才提交新数据。迁移失败或缺少迁移路径时保留原数据，显示节点不兼容占位卡片，其他节点仍可使用。 |
| 节点持久化归属 | 插件定义节点参数、资源引用、自定义字段的语义和 schema。这些持久节点状态随节点保存在 Convax 仓储，通过 Convax API 修改；Convax 拥有校验、修订冲突、持久化和迁移。Session 消息仍归 DSH，真实文件保留原位置，凭据和用户级设置仍归各自服务。 |
| 输入连线 | 多个文件或文件夹节点可连向同一个 Chat。新建 UI 连线时只解析一次来源，并将原生引用插入该 Chat 当前 thread 的草稿。 |
| 执行触发 | 输入连线声明输入关系，交付连线记录产物。新增连线或上游内容变化不自动启动下游任务。用户或插件提供的明确动作触发执行。自动工作流由专门的工作流插件拥有，Convax 核心拥有画布及连线关系。 |
| Agent 画布工具 | Convax Host 提供工具，让 agent 通过与 UI 相同的命令查询画布、添加文件节点、建立连线、移动节点和整理布局。默认目标为调用方 Session 所属 Chat 的画布，跨画布操作显式指定目标。仅停用 renderer 时工具仍可使用。涉及运行中 thread 的删除沿用已确定的确认、停止和归档规则。 |
| 输入变化 | 新连线引用只进入当前 thread 草稿。删除引用保留连线；发送按原生流程清空草稿，不补回引用。已保存连线、切换 thread 和重新打开画布都不插入引用。 |
| 引用准备失败 | 显式引用解析失败时，报告受影响资源并保留已有草稿和连线。不插入过期引用，也不把该连线变成隐藏的发送依赖。草稿内其他原生内容仍可发送。 |
| 工作目录 | 从文件夹 A 创建 Chat 时，使用 A 的确切路径作为默认项目，新 thread 继承该项目。之后连接 B 只增加一条草稿引用，仍保留 A 项目。空画布中新建 Chat 直接使用该画布保留的默认目录，不打开选择器；每个 thread 保留 DSH 工作目录控件。 |
| 输出 | agent 明确交付的文件自动在 Chat 附近生成文件节点，并建立 Chat 到文件的连线。普通目录变化刷新已有引用，不把每个变化文件都导入画布。 |
| 关闭 Tab | 关闭 Tab 只关闭视图，保留画布和后台 thread 执行。画布可以重新打开，任务完成或等待审批时提供提醒。切换 Tab 同样保留运行任务。 |
| Host 与 renderer 拆分 | Convax 拆为 `dsh-convax-plugin-host` 和 `dsh-convax-plugin-renderer`，分别控制生命周期。常规停用只关闭 renderer，Host 继续可用。 |
| 停用 renderer | 恢复标准 DSH 界面，Convax Host 继续持久化、显式资源解析和交付处理。运行中的 thread 仍可通过 DSH 原生对话使用。重新启用 renderer 时展示 Host 当前的画布状态。 |
| 停用 Host | 保留画布数据，DSH Session 的执行和历史在没有 Convax 时仍可使用。停用不触发删除时的停止并归档行为，Host 恢复后继续画布集成。 |
| Host 不可用期间的交付 | Host 恢复时，根据 DSH 持久交付记录，将 Host 不可用期间交付的文件补到原画布。每次交付只处理一次，保留用户对产物节点的显式移除，不通过重跑任务重建画布。仅停用 renderer 时，Host 仍照常处理交付。 |
| DSH 扩展原则 | 优先使用 DSH 已有 API 和普通插件注册。Convax 拥有产品专用状态与协调；KV 缺少跨记录事务不是 DSH bug。新增 DSH API 需要独立成立的通用需求。已有 UI 嵌入改动另行评估缩减。 |
| 删除 Chat 或画布 | 删除时停止并归档其 thread，保留历史记录。有运行任务时先确认再删除。文件和文件夹内容保留。 |
| 容量 | 不增加节点数、Chat 数或并发 thread 数的产品配额，也不要求用户选择容量档位。 |

### DSH 已有集成点

以下结论列出当前实现和后续集成使用的 DSH 源码接口。

- Desktop 通过 Desktop profile 运行共享 Web 应用。Cordis 插件是运行单元，组合包组织可安装的 profile 贡献；同一个包可以同时携带组合包和客户端元数据。参见[应用组合](../../../../docs/architecture.zh.md)、[组合包](../../../../packages/bundle/README.zh.md)和[客户端模块](../../../../packages/client/modules/README.zh.md)。
- 安装后的 Host 插件以受信任代码运行在 Host 进程中。DSH 现有插件机制不为任意第三方画布渲染器提供沙箱；若要提供这类扩展模型，需要单独明确设计。参见[插件安装与信任](../../../../packages/boot/plugin-manager/README.zh.md)。
- 原有 `conversation.content` Factory 可在显式 `SessionProvider` 下嵌入原生对话内容。Convax 复用对话流与输入框，自己拥有外围卡片布局，不依赖新增 DSH dock API。每个 Session 绑定保留一个编辑器。参见 [Factory 声明](../../../../packages/client/ui-conversation/src/client/contract/slots.ts)、[嵌入式对话宿主](../../../../packages/client/ui-subagent/src/client/sidebar-chat/index.tsx)和[输入中心](../../../../packages/client/ui-conversation/src/client/input/hub.ts)。
- 原生 Workspace 导航可能切换主 Session 或迁移其草稿。Convax 必须让卡片内 thread 选择和资源引用归各自所有者管理。在承诺所有 DSH UI 代码不变之前，需要另行评估已有 UI 适配。参见 [Factory 动作](../../../../packages/client/ui-conversation/src/client/apply.ts)和 [Workspace 导航](../../../../packages/client/ui-workspace/src/client/navigation.ts)。
- 插件可通过优先级替换 `root` slot。这不会转移现有布局子 slot 的所有权：设置、Plugins 页面和 `shell.overlay` 仍需要合法宿主。参见 [slot 所有权](../../../../docs/subsystems/slots.zh.md)和[布局注册](../../../../packages/client/ui-layout/src/client/index.ts)。
- Session 有当前生效的工作目录，原始项目仍决定项目归属和沙箱可写根目录。因此，连入一个文件夹引用不能静默增加另一个可写项目。参见[工作目录语义](../../../../docs/subsystems/working-directory.zh.md)。
- DSH 的 `present` 工具在调用方 Session 中记录明确的文件交付，可直接作为输出节点的数据来源，无需扫描任意文件系统变化。参见[文件交付](../../../../packages/deliverables/tool-present/README.zh.md)。

### 插件组成

对用户提供一个可安装的 Convax 产品组合包，包含分别控制启停的 `dsh-convax-plugin-host` 和 `dsh-convax-plugin-renderer`。包位于 `packages/convax/plugin-host` 和 `packages/convax/plugin-renderer`，归入仓库明确声明的可选产品分类。组合 DSH 原有对话插件，同时使画布数据和后台集成独立于 renderer 启用状态。

| 部分 | 职责 |
|---|---|
| `dsh-convax-plugin-host` | 拥有画布、节点、连线、Chat 到 Session 绑定、显式引用解析、交付投影和删除协调，暴露类型化命令与查询，在画布 renderer 不存在时仍可工作。 |
| `dsh-convax-plugin-renderer` | 拥有画布界面、应用 Tab、Chat 容器、thread 选择、预览和交互状态，通过显式 Session 绑定嵌入 DSH 对话 Factory；停用后恢复 DSH 原生界面，同时保留 Convax Host。 |
| Convax 组合包 | 将 Host、renderer 贡献和 DSH 依赖组合进 Desktop profile，区分仅停用 renderer 与停用 Host 或整个组合包。 |
| Convax agent 工具适配器 | 在 Host 生命周期下注册已确定的图工具，根据真实 Session 绑定及显式跨画布目标定位操作，调用与 UI 相同的 Host 命令，复用删除确认及停止归档行为。除非依赖或生命周期需要，否则无需独立成包。 |

Host 与 renderer 分别控制启停，不将二者生命周期合并为一个插件注册项。组合包元数据和工具适配器无需引入空包装包或并行的 agent 运行时。Host 的领域行为不能依赖 renderer 挂载、浏览器状态或活动 Tab。

节点类型提供方通过下述公开接口分别注册 Host 定义和客户端渲染器。renderer 是否可用不决定 Host 节点类型能否准备输入。提供方可用性也与节点是否存在于持久画布中相互独立：画布在无法识别节点类型时仍能打开，保留其数据并显示已约定的占位卡片。

完整画布界面占用 DSH 布局插件拥有的公开 `shell.workspace` slot。DSH 保留根界面所有权、全局浮层、设置、Plugins、主题呈现和面板宿主。全窗口工作区启用时，原生侧栏和右栏内容保留挂载但隐藏；选择全局面板时恢复原生布局。移除工作区贡献后恢复原对话界面。保留原生插件注册项，不通过 profile patch 停用，也不复制其实现。运行时启停变化遵循 DSH 的模块重载支持；需要重启时，不能将已保存偏好呈现为已经生效。

### 状态归属与存储

| 数据 | 建议所有者 | 持久化方式 |
|---|---|---|
| 画布身份、标题、节点、连线、Chat 默认值、thread 绑定 | Convax Host 领域 | 应用数据位置下的版本化 Convax 仓储；保存 DSH Session 身份，不复制消息。 |
| 节点类型身份、数据版本和序列化节点数据 | Convax 拥有存储封装，节点插件拥有其数据语义 | 将类型身份和数据与运行时注册分开保留。插件提供版本化迁移，Convax 校验并提交成功升级，保留可恢复的旧副本。 |
| 可恢复的迁移副本和迁移记录 | Convax 仓储 | 将带版本的旧数据及升级结果保存在应用管理的数据中，独立于提供方安装目录和启停生命周期。在明确实现保留策略前持续保留。 |
| 消息、工具事件、模型选择、执行和历史 | DSH 现有 Session 与 agent 服务 | 沿用 DSH 持久化，Convax 通过公开服务读取状态。 |
| 真实文件和目录 | 原文件系统位置 | 保存引用，不把项目复制进画布数据库。 |
| 已打开 Tab、活动 Tab、视口与查看偏好 | Convax 窗口偏好 | 按窗口和画布标识保存，与画布是否存在分开；不把画布引擎的布局快照作为领域存储格式。 |
| 选择、拖动、连线手势和临时加载状态 | Convax 客户端交互状态 | 保存在内存中，持久图修改通过 Host 命令提交。 |

DSH 默认组合将 Session 数据存放在 `$DSH_HOME/sessions`，存储放在 `$DSH_HOME/storages`。Convax 使用同一已解析 home，但拥有自己的数据库实现，不注册替代 DSH 存储后端。参见[基础组合](../../../../packages/bundle/base/cordis.patch.yml)、[domain 存储](../../../../packages/storage/storage-domain/README.zh.md)和 [Session 持久化](../../../../packages/session/session-persistence-jsonl/README.zh.md)。

Convax 自己拥有 SQLite，因为图修改需要多记录事务和修订校验。这项需求不改变 DSH 通用 KV 的保证。各替代方案的所有权代价不同：

| 选项 | 已有能力 | 所有权代价 |
|---|---|---|
| DSH domain 配合 JSON `single` | schema 校验、有序耐久写入和原子文件发布。 | 它重新发布整个 unit，不暴露 Convax 所需的跨记录事务；补齐这些要求会扩大 DSH 存储职责。 |
| DSH domain 配合 SQLite | SQL 记录上的既有 domain API。 | 仅后端使用 SQL 不会暴露图事务或协调 Session 写入；扩展通用 API 会增加无关维护。 |
| Convax 自有 SQLite 仓储 | 单一写入者下的图事务、修订校验、恢复副本和 schema 升级。 | Convax 维护自己的持久化与协调。DSH Session 日志、格式和存储实现保持不变。 |

[存储提案](../architecture/2026-07-24-domain-kv-storage-and-workspace.zh.md)、[JSON 后端](../../../../packages/storage/storage-json/README.zh.md)和 [SQLite 后端](../../../../packages/storage/storage-sqlite/README.zh.md)保留各自的 DSH 保证。可复用业务插件在符合自身需求时可使用这些服务；图插件提交 Convax 命令，不增加第二个图写入者。

### 公开接口

下列 Convax 自有接口复用 DSH 已有服务。准确导出名称与参数由源码声明拥有；概念性的 UI 集成不代表新增通用 DSH API。

| 所有者 | 接口 | 必须提供的行为 |
|---|---|---|
| Convax Host | `registerNodeType(definition)` | 注册稳定且带提供方命名空间的类型身份、数据版本与 schema、命名端口、显式引用解析和版本化迁移。拒绝重复的活动类型身份，返回释放函数。 |
| Convax renderer | `registerNodeRenderer(typeId, renderer)` | 渲染已校验的节点快照并提交 Host 命令。注册独立于 Host 定义；渲染器缺失时显示占位卡片，不停用 Host 显式引用解析。 |
| Convax Host | `workspace`、`watch`、`execute` | 返回带修订号的快照，发布已提交变化，接收带操作身份和预期修订号的类型化命令。UI、节点插件和 agent 工具通过 DSH 类型化 Remote 共用此服务。 |
| Convax Host | `prepareReference(canvasId, nodeId, signal?)` | 通过当前节点提供方及既有文件系统策略解析一次资源，供显式插入输入框。复查节点与提供方身份，响应取消，不修改图状态或项目目录。 |
| Convax 数据库 | 本地事务和单调 schema 升级 | 原子读取前置条件并写入图记录和回执，提交后发布缓存状态，保留恢复副本。DSH 存储 API 保持不变。 |
| Convax Session 物化器 | 固定的创建与 fork 预留 | 在 thread 账本保存一份预留，使用原生 Session preparation、persistence 和 `buildForkSeed`，再绑定实际 Session。回复丢失后沿用同一身份恢复，拒绝变化的请求。 |
| Convax 生命周期检查 | 既有 `agent/pre-step` hook | 拒绝删除中或绑定目标缺失的 Chat 及其 subagent 后代进入模型步骤。原生发送和已入队消息保留 DSH 原有行为；该 hook 不承诺入队前拒绝。 |
| DSH 客户端 UI 与 Convax 布局 | 既有 Conversation Factory 与共享应用壳宿主 | 复用全局 UI 宿主和 `conversation.content`；Convax 拥有卡片布局及局部选择。已有嵌入适配保留独立评估，不扩为新的 dock API。 |
| Convax 资源服务 | 基于 DSH 既有文件系统服务浏览和预览 | 使用明确资源访问，不制造隐藏 Session；预览权限与为 agent 增加可写根目录的授权保持独立。 |

注册与订阅通过 Cordis effect 管理并释放。异步准备和迁移接收取消信号；提供方移除时取消该提供方尚未完成的准备和迁移，阻止过期结果提交。已接纳任务保留其有日志输入。跨服务身份使用品牌类型。配置、持久记录、插件数据 schema 和传输请求分别在对应解析入口校验。

### 仓储记录

图记录、唯一性索引和恢复回执放在同一 Convax 自有 SQLite 数据库中。thread 操作记录同时拥有 Session 预留阶段，不需要并行的 DSH 操作账本。

| 记录 | 保存的事实 |
|---|---|
| 画布 | 稳定身份、标题、图修订号和正常或删除中状态。 |
| 节点 | 稳定身份、所属画布、类型身份、数据版本、序列化数据、位置尺寸和节点修订号。运行时提供方状态通过注册情况推导。 |
| 连线 | 稳定身份、两端节点与端口身份、输入顺序和用途。输入连线记录引用关系，不注入发送；交付连线记录产物，不形成执行循环。 |
| Session 绑定 | 以实际 DSH Session 身份为键的唯一记录，包含画布、Chat 身份、thread 归属和交付投影起点。Chat 提供方缺失时仍可读取。 |
| 操作 | 操作与请求身份、受影响记录与 Session、耐久阶段、结果或可恢复失败，以及适用时的删除确认。thread 操作还保留固定 Session 预留与 fork 前缀。 |
| 交付回执 | Session 身份、耐久事件序号及文件索引、投影节点与连线身份，以及已处理或显式移除状态。重放游标与这些回执保持一致。 |
| 迁移副本 | 节点身份、源与目标数据版本、原始数据及修订号、迁移结果。仓储 schema 升级另保留可恢复的数据库副本。 |

端口具有稳定身份、方向和明确接纳的数据种类。文件和文件夹节点提供资源引用，Chat 输入端口接收这些引用。连线持久化端口身份，避免提供方变化后被静默重新解释。新建连线根据可用定义校验；提供方缺失时保留既有连线。图变化不请求执行或递归求值。

### SQLite 事务、所有权与升级

Convax 通过自己的数据库所有者，在 DSH 已解析应用 home 下打开 `storages/convax-canvas.sqlite`。版本化仓储从同一个只读快照导入前驱 `storages/convax.sqlite` 的图与匹配的 Session 操作预留。前驱文件及未匹配记录保留供恢复使用，警告标明未匹配操作 id。自有数据库升级保留原数据库副本。开发启动器通过 DSH 已有 home 覆盖机制传入仓库 `.convax`。

一个 Host 拥有数据库写入者和缓存。多个窗口连接该 Host；竞争写入者收到 `storage-in-use`。加载缓存前取得所有权，依赖工作关闭后释放。持续持有的前驱租约阻止旧 Host 写入迁移来源；来源与目标路径必须对应不同文件。仅靠 SQLite 语句锁无法协调过期缓存。这约束竞争写入者，不限制窗口、画布或 thread。

对既有画布的修改携带 `canvasId`、`operationId` 和 `expectedRevision`。在同一事务内读取耐久修订号，校验记录约束和 Session 绑定唯一性，应用全部图变化，记录操作结果，再递增修订号。冲突时不写入并返回当前修订号；重复已提交操作时返回已记录结果，使用不同请求参数复用同一操作身份则拒绝。外部文件访问、Session 调用和异步插件工作在 SQL 事务外执行，准备结果提交时重新校验源修订号。

耐久提交后，整体更新 Convax 缓存并发布新修订号。通知失败不能回滚已提交写入。结果未知时先检查回执再重试，无法确定的状态暂停依赖修改。不能用多次 KV 写入模拟事务或静默重置损坏数据。损坏或不支持的版本保留介质并报告恢复失败。

区分 SQLite 物理 schema、Convax 仓储 schema、节点数据版本和插件发布版本。仓储升级在独占写入所有权下执行，修改 schema 前生成可恢复数据库副本。节点迁移在副本上变换，不产生外部副作用，再校验结果。只有原节点和提供方注册仍然有效时，才在同一事务中提交旧数据副本、新数据及版本、迁移结果和修订号。缺少迁移路径或迁移失败时保留原数据并显示约定的不兼容占位卡片，单个节点失败不重置其画布。

### 显式引用与失败恢复

画布连线声明关系。UI 连线手势在图命令成功后调用一次 `prepareReference`；Host 不在发送时扫描入边。

1. 捕获发起动作的 Chat 和当前 thread 草稿。通过当前节点提供方、可选的 `prepareInput` 及既有文件系统策略解析选中来源。返回路径前复查节点数据、兼容性、提供方身份与取消状态。
2. 通过原生输入框引用 API 插入一次已解析路径。操作局限于捕获的 thread，不分发到其他 thread 或后来选中的草稿。解析失败或取消时保留已有草稿内容和连线，报告资源，不插入过期值。
3. 用户可删除引用而保留连线。发送遵循原生草稿生命周期；清空草稿、切换 thread、重新打开画布或重载已保存连线都不重新插入引用。
4. 仅发送该草稿保留的原生消息及引用。保留 DSH 普通日志和草稿保留行为，图修改不重写已接纳消息。Convax 的 `agent/pre-step` 检查阻止删除中或绑定目标缺失的 Chat 及其 subagent 后代进入下一模型步骤，不改变入队语义。

引用保持 DSH 普通路径语义，不冻结目录树未来字节，也不扩大可写根目录。停用 renderer 后，Host 资源 API 和交付恢复继续可用。原生 Web、SDK、ACP 和 headless 发送保留原协议；Convax 不增加 prepared-input 事件或隐藏的图派生上下文。

### Session 协调与交付投影

创建或 fork thread 时，先在同一 Convax thread 账本保存意图与固定 Session 预留。物化器使用 DSH 原有 Session preparation、persistence、Workspace 关联和 `buildForkSeed` API。完整 seed 一次 append，记录 Session 完成后再提交唯一图绑定。回复丢失后恢复保留 Session id 与固定 fork 前缀；已完成预留不会重建用户主动移除的 Workspace 关联。持久 seed 损坏时，在原 pending 身份下明确失败。Session Controller 不增加耐久操作 API。

完成适用确认后，Convax 持久化删除状态、受影响 Session 和未完成创建或 fork 意图。它阻止新绑定与模型步骤，处理晚到创建结果，再通过原生 Workspace 归档、停止事件和活动查询处理各 thread 及其 subagent 后代。等待 Agent 与所属 job 结束后移除图，保留操作记录、历史和交付墓碑。重试已归档 Session 时明确再次请求停止；归档成功本身不证明无活动。部分失败保持可见且可重试。参见 [Workspace 归档处理](../../../../packages/workspace/workspace/src/index.ts)。

使用 `(SessionId, event sequence, file index)` 作为每个 `deliverables/presented` 文件项的投影键。在同一 Convax 事务中创建输出节点和交付连线并保存回执。只有该事件全部文件项已有回执且前序事件完成后，才推进事件级重放游标；并发处理不能跳过未完成项。不同交付事件保持独立，即使指向相同路径。移除产物节点时保留标记为显式移除的回执。面向删除中或已删除目标的交付记录为已抑制，不能恢复该目标。实时观察与重启重放共用同一操作，均不重跑任务；仅停用 renderer 时 Host 继续处理。

### 视图状态、资源与 agent 操作

显式持有每个展示中的 Session 引用，在同一客户端内，每个 Session 绑定只挂载一个可编辑输入框。草稿保存在共享 DSH 草稿所有者中，独立于 Chat 卡片挂载；切换 thread、关闭 Tab 或切换根 renderer 不丢弃草稿。应用级通知和审批观察者位于单张卡片之上。释放视图引用不请求停止 Host agent。参见 [Session 引用生命周期](../../../../packages/api/session-controller/README.zh.md)和[引用释放](../../../../packages/api/session-controller/src/client/sessions/service.ts)。

文件节点保留选中的绝对资源引用。路径缺失或移动时，显示可重新关联的不可用资源，不静默删除或猜测新位置；重新关联影响后续显式引用解析，保留已有草稿和已接纳历史。重复引用可保留为不同节点。Convax 浏览和预览使用 DSH 已有文件系统服务及访问策略；连接文件夹不扩大沙箱可写根目录。

Agent 工具根据调用方 Session 绑定确定默认画布。未绑定的调用方必须显式指定画布，跨画布操作也显式指定目标。工具与 UI 提交相同的带修订号命令，传递取消信号，通过 DSH 人类交互完成运行中 thread 的删除确认，不依赖 renderer。关闭画布 Tab 保留任务。首版建议沿用 DSH 现有窗口和退出生命周期，不增加独立守护进程；退出应用后的任务行为仍待产品确认。

### 实施顺序与验证

以下三个产品步骤各自可演示。实现使用 Convax 自有持久化与协调，基于 DSH 已有 API。新增通用 DSH 运行时 API 不是前置条件；剩余 UI 适配另行评估。

| 步骤 | 交付内容 | 依赖 | 可观察的完成状态 |
|---|---|---|---|
| 1. 持久文件画布工作台 | Host、renderer 拆分，共享应用壳验证，SQLite 事务与仓储，公开节点和端口注册，文件及文件夹浏览预览、图编辑和多画布 Tab。 | 开发环境和具体 UI、存储接口设计；UI 组合与存储可并行。 | 添加不同项目引用，排列和连接节点，切换 Tab，重启后恢复已保存工作台；停用 renderer 恢复 DSH 原生界面。 |
| 2. Chat 输入与交付闭环 | 完整复用 DSH 对话和多 thread，加入耐久创建及 fork 绑定、草稿、通知、显式输入框引用、文件交付投影和协调删除。 | 步骤 1；耐久 Chat 绑定完成后，显式引用解析与交付投影可并行。 | 新文件夹连线向当前草稿插入一次引用，交付文件生成节点，重启和重放保留 Session 与产物，确认删除后停止并归档 thread。 |
| 3. 插件扩展与完整验收 | 提供方启停和迁移、恢复副本、agent 画布工具、产品组合，以及完整功能之间的验证。 | 步骤 1、2；仓储和注册机制完成后即可提前推进迁移。 | 提供方变化后扩展节点可恢复，agent 不依赖 renderer 修改画布，完整 Desktop 流程能承受约定的故障与生命周期变化。 |

三个步骤均已有实现与针对性验证。真实 Loader 测试覆盖耐久创建和 fork 身份、唯一绑定、跨进程恢复、独立于 renderer 的交付、确认后停止归档删除、提供方重新加载，以及保留恢复副本的仓储升级。嵌入式 UI 测试覆盖独立的原生 Conversation、草稿保留、局部导航及兼容占位。真实模型测试验证显式原生资源引用和文件交付，并在停用 renderer 后调用五个画布工具；外层测试检查 SQLite 耐久图记录及源文件内容保持不变，不依赖模型文字自述。

#### 步骤 1：持久文件画布工作台

##### Desktop 与对话组合验证

准备 Node >=24.9 和工作区依赖，建立 DSH 原生 Desktop 冒烟基线，根据嵌入输入框、指针、键盘和布局要求选择画布交互依赖。通过受支持的 DSH profile 组合进行验证，绑定测试准备阶段已由 DSH 打开的 Session，不另写对话实现，也不增加临时的生产 Session 创建路径。修改所有者前，先明确共享应用壳和卡片内导航的具体接口。

Convax 卡片组合与原生 Conversation 所有权保持独立。验证不同 Session 不串草稿、焦点、工具或审批，挂载另一展示前释放前一个编辑器。检查设置、Plugins、账号流程、浮层和主题。已有 DSH UI 嵌入改动需要独立缩减评估；这项验证不代表已具备耐久 Chat 绑定。

##### 耐久 Host

实现 Convax 自己的 SQLite 所有者、图约束、操作回执、恢复副本和已提交变化订阅。DSH 存储声明、后端和路由保持不变。明确且单调的仓储版本拒绝不支持的写入者，并在失败时保留介质。

验证多记录回滚、耐久修订比较、操作去重及参数不匹配、一致缓存发布、未知提交结果恢复、重启和 Host 写入所有权竞争。持久图编辑依赖这些保证；Session 创建、prompt 接纳和迁移逻辑不放进首个存储改造。

##### 文件工作台

从开始就实现节点封装和独立的 Host、客户端注册，再通过这些公开接口注册文件、文件夹类型。加入应用级浏览预览、目录子项拖入、位置尺寸与连线、自动保存、画布创建列表与重开，以及按窗口保存视口偏好的浏览器式 Tab。首个耐久版本就将未知节点数据和连线保留为占位。

验证移除引用节点不改变真实文件，路径缺失时仍可见且可重新关联，文件访问遵循既有策略，关闭 Tab 保留已保存图。完成这些工作即交付步骤 1：可用的持久文件工作台。耐久 Chat 和输入执行在步骤 2 交付。

#### 步骤 2：Chat 输入与交付闭环

##### 耐久对话与删除

将 Convax thread 账本、原生 Session 物化器、唯一绑定恢复、内嵌 Chat/thread UI 和删除协调器作为独立工作包。对外提供完整创建、fork 或删除前，先由 Convax 保证耐久身份和晚到结果处理。复用原生 Session 控件、草稿保留和应用级完成与审批观察。

验证多个 Chat、thread 独立执行，Workspace 选择局限于卡片内，关闭 Tab 和 renderer 回退行为正确，重启或回复丢失后复用实际返回的 Session。在创建和删除阶段注入失败，包括创建未完成时删除；从外部确认停止和归档状态。关闭视图或停用 Convax 始终区别于删除 Chat。不能采用不幂等的临时创建路径，也不能把归档成功当作任务已停止。

##### 原生输入框引用

显式解析新建 UI 连线，将来源插入发起方原生草稿。从文件夹创建 Chat 时，以该路径作为项目；后续连线保留项目。Convax 生命周期检查使用已有 agent pre-step hook，不增加图派生消息内容。

验证单次插入、thread 所有权、保留连线的引用删除、原生发送与清空、重开已保存连线、提供方取消及源变化拒绝。DSH 原生发送与 Convax 发送均不自动添加连入资源。通过测试覆盖不变的原生发送路径与 pre-step 拒绝，不新增 Session 事件或 SDK 投影。

##### 交付文件

通过同一个 Host 投影消费 DSH 耐久交付事实，同时用于实时观察和恢复补齐。逐个文件项共同提交输出节点、交付连线和回执；只有前序项全部完成才推进连续事件游标。产物显式移除及删除中、已删除目标通过同一仓储命令协调。

验证单事件多文件、同路径多次交付、文件项之间中断、实时和重放重叠、产物移除后重放，以及删除期间交付。分别停用 renderer 和 Host，验证持续处理与恢复补齐的差异。与耐久对话和原生草稿引用一起，完成步骤 2：Chat 输入到交付文件闭环。

#### 步骤 3：插件扩展与完整验收

##### 提供方生命周期与迁移

在 Convax 数据库所有者内部实现仓储升级，与节点迁移策略区分。保留数据库恢复副本、纯数据变换、原子新旧数据记录、修订检查与提供方取消。使用测试专用提供方演示公开注册，无需另加已发布产品包。

验证提供方卸载重载、客户端渲染器缺失但 Host 提供方可用、Host 提供方缺失但数据保留、成功升级、缺少迁移路径、无效输出、取消和升级中重启。失败时不能覆盖旧数据。本步可在仓储与注册机制完成后推进，无需推迟初期 UI 验证，也无需提前制造一次人为的 schema 升级。

##### Agent 工具与集成验收

将已有 Host 命令服务包装为 DSH agent 工具，支持画布查询、文件节点、连线、移动和排列。复用实际 Session 定位、显式跨画布目标、取消、冲突结果和删除确认。补齐组合包元数据和 profile 集成，保留 Host、renderer 分别控制及原生界面回退。

执行一条完整验收路径，覆盖多个画布与 Chat、连线文件夹、发送 prompt、明确交付文件、关闭重开 Tab、renderer 回退、Host 补齐和提供方恢复。查询耐久图状态验证 agent 修改，不依赖工具文字自述。第三个里程碑覆盖全部已确定方案，不要求加入新工作流执行语义或第二套 Session 存储。

#### 评审、并行与验证

可独立使用的 Convax 工作分别评审。DSH 缺陷修复需要独立复现与测试；Convax 需求不自动成为修改共享 API 的依据。保留的 UI 适配独立评估，每项所有权调整完成后先通过针对性 E2E 再继续。

每步同步提交受影响 README、JSDoc 和 locale 更新、针对性单元及真实 Loader 组合测试，以及必需的无需密钥用户或模型可见快照。持久类型变更确认和必要升级指南随引入变更一起提交。纯画布几何和 UI 预期保留在所属模块，Session 驱动用例使用记录回放框架。Session 生命周期或事件变化更新两种 SDK 投影。并发和重启 fixture 使用独立临时数据库、确定性同步屏障、明确就绪信号及等待完成的清理，不依赖固定睡眠。浏览器自动化使用仓库页内目录选择覆盖配置，测试原生选择器时除外。

宣称实现完成时，根据实际 diff 选择检查，并在最新 `build:artifacts` 后执行 `build:check`，或执行 `build`；UI 冒烟成功不等于编译通过。最终执行适用的文档和包检查，凭据可用时增加真实模型交付文件冒烟；缺少凭据时明确报告证据缺口。不默认在每一步运行全量测试。

真实 API 测试遵循[带 key 测试策略](../../../../docs/testing.zh.md)：`vitest.e2e.config.ts` 从仓库根 `.env` 读取 `DEEPSEEK_API_KEY`，没有 key 时测试自行跳过。凭据不进入文档、fixture 或输出。`packages/convax/plugin-host/tests/chat-real-model.e2e.ts` 通过生产 Web profile 验证显式原生引用、Session prompt、实际文件内容和交付投影。`packages/convax/plugin-host/tests/graph-real-model.e2e.ts` 在停用 renderer 时验证五个模型工具调用和耐久图变化。两者均已有带凭据验证；`apps/cli/tests/profiles/headless/tests/real-model.e2e.ts` 独立拥有已交付 headless 路径。

撤销重做、用户主动删除 Chat 或画布后的恢复，以及退出应用后任务是否继续，仍是待确认的明确产品决策。它们与已经要求的崩溃恢复、Session 历史保留及停止归档删除行为分开。记录建议默认值，不将其作为步骤 1、2 的前置条件，也不静默加入已确定验收标准。

建议默认值为普通图编辑支持撤销重做，删除后图结构和 thread 入口可以恢复，但不自动重启旧任务。首版应用生命周期仍建议沿用 DSH 现有行为，不额外增加守护进程。这些建议尚未成为已确认产品要求。

## 已考虑的替代方案

**画布旁固定一个全局聊天区。** 已选择 Chat 节点，让同一画布可以容纳多个独立连线的对话，每个对话有自己的 thread。

**每个项目拥有一组画布。** 已选择应用级画布，让用户不必先选定一个项目作为容器，就能组织多个项目的文件和文件夹。

**以独立画布文件作为主要存储。** 已选择应用管理的存储，让用户创建和重新打开画布时无需管理各自的保存位置。这项决策不定义未来的导出格式。

**关闭画布 Tab 时停止任务。** 关闭视图保留正在执行的任务；显式删除则按已约定的确认行为停止并归档 thread。

**每个交付文件都手动加入画布。** 已选择从明确交付自动生成节点，让任务结果直接出现在图上，无需用户再次操作。

## 验收标准

- Desktop 展示应用级画布 Tab，支持文件、文件夹、Chat 节点及连线，不设置产品数量配额。
- Convax Host 自己拥有 SQLite 事务、修订检查、schema 升级与恢复副本，不扩展 DSH 存储。DSH Session 存储保持独立；单一 Convax thread 账本协调部分完成的图与 Session 操作。
- Chat 使用现有对话流和输入框创建、切换多个由 DSH 支撑的 thread。
- 每个 DSH Session 在 Convax 中只有一个 Chat 绑定；DSH 原生视图保留同一身份，在另一个 Chat 延续其历史时创建独立的 fork Session。
- 文件、文件夹、Chat 和其他 DSH 插件提供的节点类型使用同一套公开注册机制，插件安装和生命周期继续由 DSH 拥有。
- 停用或卸载节点提供方时，将节点数据、位置尺寸和连线保留为可移动、可删除的占位卡片；画布和其他节点仍可使用，兼容提供方恢复后还原原节点。
- 节点升级使用独立数据版本和插件提供的迁移函数。Convax 保留可恢复副本，在提交前校验；迁移失败或缺失时保留不兼容数据并显示占位卡片。
- 持久节点业务状态随节点保存，并通过 Convax API 更新；插件数据语义不引入第二个画布数据写入者，也不重复存储 DSH Session 数据。
- 新建 UI 连线只向当前 thread 草稿插入一次原生引用。删除引用保留连线；清空草稿或重新打开已保存图不会补回引用。已发送引用可从原生 Session 消息重建。
- 显式引用解析失败时指出资源，保留草稿和连线，不插入过期值。已保存连线不会阻塞或增补原生发送；Chat 删除接纳检查仍然生效。
- 显式引用解析失败标明资源，保留草稿和连线，不插入过期值。已保存连线不阻塞或扩充原生发送；删除中或绑定目标缺失的 Chat 不能进入下一模型步骤。
- Agent 图工具与 UI 使用同一套 Host 命令，根据 Session 绑定确定默认画布，支持显式指定目标的跨画布操作，且不依赖 renderer 启用。
- 从文件夹创建的 Chat 及其新 thread 使用约定工作目录默认值，后续文件夹输入不隐式改变目录。
- 明确文件交付生成已连线的输出节点，重新连接或重放不重复插入。
- 关闭 Tab 保留画布和运行中的 thread，任务完成和待审批状态仍可发现。
- 仅停用 `dsh-convax-plugin-renderer` 后恢复标准 DSH，`dsh-convax-plugin-host` 继续节点持久化、显式资源解析和交付处理；renderer 重新启用时展示 Host 当前状态。
- 停用 Convax Host 保留画布数据，不停止或归档 DSH 原生 Session，后者的执行和历史仍可独立使用。
- Host 恢复时根据 DSH 持久记录补齐其不可用期间的交付，不重跑任务、不重复生成交付，也不还原用户已移除的产物节点。
- 确认删除后停止并归档受影响 thread，保留历史和原文件，部分失败后仍可恢复。
- 在宣称实现完成前，针对事务和缓存发布、回复丢失后的 Session 创建、写入所有权、提供方移除及应用壳回退，验证失败、冲突、重启和组合行为。

## 风险

替换根 UI 却不保留其全局宿主，会导致已有操作仍被注册但不可见。复制对话代码也会随着 DSH 插件演进丢失已有行为。因此，设计依赖明确组合，而不是私有组件导入。

图持久化、Session 持久化和文件系统写入不共享事务。部分失败后 Convax 保留固定身份与 pending 操作，对损坏或不支持的数据明确报错。针对性 Loader 和真实模型测试覆盖自有数据库、Session 恢复与删除路径；剩余 UI 适配仍需独立缩减评估。
